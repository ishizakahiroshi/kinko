# kinko

秘密を暗号化して保管し、**必要なときだけ 1 件ずつ取り出す** CLI です。

```
kinko get myapp/db_password
```

## なぜ作ったか

開発機で AI コーディングツールを並行して動かしていると、平文の設定ファイルに置いた
秘密がうっかり画面へ流れる事故が起きます。

- `grep` のパターンが広すぎて、目的の行の隣にあった API キーまで出た
- 設定ファイルの差分を確認したら、改行コードの違いで全行が差分になり、全部出た
- ファイルを読んで一部だけ表示するつもりが、伏せ字の処理を書き忘れた

どれも原因は同じで、**ファイル全体を読める**ことが前提になっています。「気をつける」で
は防げません。人が注意で防ぐ設計は、注意が切れた瞬間に破れます。

そこで、ファイル全体を読む経路そのものを無くします。名前を指定して 1 件だけ取り出す
形にすれば、取り違えても手に入るのは 1 件です。**事故の上限が変わります。**

## インストール

```sh
go install github.com/ishizakahiroshi/kinko@latest
```

Go 1.25 以上が要ります。

## 使い方

```sh
# 保管庫を作る（パスワードを 2 回聞かれます）
kinko init

# 秘密を入れる。値は入力を求められ、画面には出ません
kinko add myapp/db_password

# 1 件だけ取り出す
kinko get myapp/db_password

# 何が入っているかを見る（値は出ません）
kinko list
kinko list myapp/

# 消す
kinko rm myapp/db_password

# 別ファイルへ書き出す（バックアップ）
kinko export backup.age
```

### kinko run — 実値をディスクへ置かない

これが本体です。参照名だけを書いたテンプレを用意します。

```sh
# app.env.tmpl（このファイルはリポジトリへコミットしてよい）
DB_PASSWORD=${kinko:myapp/db_password}
API_TOKEN=${kinko:myapp/api_token}
APP_MODE=development
```

このテンプレを渡してコマンドを起動すると、参照が実値へ展開されて**子プロセスの環境
変数として**渡ります。

```sh
kinko run --env-file app.env.tmpl -- npm run dev
```

ディスクに置くのは「暗号化された保管庫」と「参照名だけのテンプレ」の 2 つだけです。
実値が平文でディスクへ載る瞬間がありません。プロセスが終われば消えます。

保管庫に無い参照があれば**起動しません**。空文字のまま起動すると「パスワード無しで
接続を試みる」ような動きになり、原因が設定ミスだと分かりにくい形で失敗するためです。

## 設計

### 暗号は自作していない

暗号化は [age](https://github.com/FiloSottile/age) に丸投げしています。鍵導出も暗号
方式も age の判断に従います。このツールが持つのは CLI の使い勝手とファイルの安全な
置き換え方だけです。

暗号を自作すると、間違いが「動くけれど守れていない」形で出ます。テストは通り、日常の
操作も成功し、破られたときにだけ分かります。そこは検証された実装へ預けます。

### 名前も暗号化する

保管庫のファイルには、値だけでなく**名前も残りません**。名前だけでも「どのサービスの
秘密を持っているか」が分かってしまうためです。

git へコミットする前提のツール（SOPS など）はキー名を平文にして差分を読めるようにし
ますが、kinko はコミットしない前提なので、隠せるものは隠します。

### 書き込みの途中で壊れない

保存は一時ファイルへ書き切ってから置き換えます。同じファイルへ直接書くと、途中で電源
が落ちたときに「半分だけ新しい」ファイルが残ります。age の暗号ファイルは途中で切れる
と全部読めなくなるので、それは秘密の全損になります。

## 限界

正直に書いておきます。

- **パスワードを忘れると取り出せません。** 復旧手段はありません。`kinko export` で
  バックアップを取ってください
- **環境変数は孫プロセスへも引き継がれます。** `kinko run` で渡した先が `env` を出力
  すれば当然漏れます。「ディスクに置かない」ための仕組みであって、渡した先の振る舞い
  までは面倒を見られません
- **画面に出す操作は防げません。** `kinko get` の結果をそのまま画面へ出せば見えます。
  変わるのは「一度に全部出る」状態が「1 件だけ」になることです
- 保管庫全体を開ける `KINKO_PASSWORD` は、`kinko run` の子プロセスへは引き継ぎません

## 環境変数

| 変数 | 用途 |
|---|---|
| `KINKO_VAULT` | 保管庫の場所（既定はユーザー設定ディレクトリ配下） |
| `KINKO_PASSWORD` | パスワード。自動処理用。**手で使うときは設定しないこと**（環境変数は子プロセスへ引き継がれ、`env` を出力する何かが 1 つあれば漏れます） |

## 既存の選択肢

先に書いておくと、**費用対効果だけで考えるなら 1Password を買うのが正解**です。
SSH agent 統合も環境変数の注入も揃っていて、年 5,000 円ほどです。無料で済ませたい
なら [SOPS](https://github.com/getsops/sops) + age で、git 管理も両立できます。
Windows なら Credential Manager だけでも足りる場面があります。

それでも作ったのは、仕組みを理解したかったからと、AI コーディングツールから秘密を
隔離するという要件に既存ツールが少しずつ噛み合わなかったからです。
