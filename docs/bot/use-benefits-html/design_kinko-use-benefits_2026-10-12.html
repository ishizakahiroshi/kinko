kinkoいつもの開発で、どう変わる？

設定の構造はAIに。
秘密の値は、起動するアプリへ。

実値入りの.envを、暗号化した金庫と、参照名だけの.env.tmplへ置き換える。設定ファイルを一緒に読んでも、秘密の値まで会話へ貼り付けずに、AIと設定を相談しやすくなります。

  • 設定の構造を見せやすい
  • 同じ秘密の更新を一箇所に
  • バックアップも暗号化

すべて架空の例です。〈秘密の値〉は説明用の表記で、実際のキーやパスワードではありません。

変わるのは、ファイルを読んだときに見えるもの。 runは実値入りの.envを作りません。ただし、AIやアプリが秘密を絶対に読めなくなる仕組みではありません。

日々の「ちょっと怖い」「面倒」が減る

01AIに設定を直してもらうとき

構造を見せるために、
値まで渡さなくていい。

「どの項目があり、何を参照するか」は.env.tmplで相談できます。実値を伏せ直す手間や、消し忘れて会話に貼る機会を減らせます。

02複数のプロジェクトで同じ秘密を使うとき

値の変更は、
共通の金庫で一度。

同じ金庫の同じ参照名を使えば、各プロジェクトの実値を貼り替えずに済みます。金庫の値を更新すると、次のrun起動から反映。起動済みアプリは再起動が必要です。

03予備を別の場所へ残すとき

バックアップの中身も、
暗号化したまま。

exportで全件を別の暗号化金庫へ書き出せます。別パスワードも設定可能。既存の出力先は上書きしません。安全な場所への保管は自分で行い、自動同期はしません。

標準では、同じユーザーの各プロジェクトから共通の金庫を使います。別の金庫を指定したプロジェクトには、その更新は届きません。参照名自体にも、外に見せたくない情報を入れないようにします。

最初に準備。普段は、アプリをrunで起動。

下のコマンドは使い方の説明です。このページからは実行しません。your-commandは、自分が信頼するアプリの起動コマンドを表します。

  1. 金庫を一度作る

    マスターパスワードを決めて確認入力します。端末では入力文字は表示されません。

    kinko init

  2. 秘密を、名前を付けて入れる

    コマンドには値を書かず、続く端末の非表示入力で入れます。同じ名前でaddすると値を更新できます。

    kinko add example-service/api-token
kinko add example-service/db-password

    値を引数に書くと、シェル履歴やプロセス一覧に残る場合があります。

  3. 名前を確認し、参照テンプレートを用意する

    listは名前だけを表示します。図の.env.tmplを用意し、秘密の部分を下の形で参照します。

    kinko list
    API_TOKEN=${kinko:example-service/api-token}

    切替後も元の実値入り.envが残れば、そのファイルを読むリスクは残ります。kinkoは既存ファイルを自動で移行・削除しません。

  4. 普段は、実値を表示せずアプリへ渡す

    金庫を開き、参照を実値に置き換えてアプリを起動します。参照先が未登録なら、アプリは起動せずエラーになります。

    kinko run --env-file .env.tmpl -- your-command

  5. 必要なときに、暗号化バックアップを作る

    新しい出力先を指定します。マスターパスワードを忘れると復旧できないため、バックアップは本体とは別の安全な場所に保管します。

    kinko export backup.age

安心して使うために、ここは覚えておく

getは、値を表示する操作。

kinko get example-service/api-tokenは、秘密の値を標準出力へ出します。画面やログ、AIの会話へ流せばそこに残ります。AIが金庫を解除してgetを実行できるなら、AIも値を読めます。

渡されたアプリは、値を読める。

アプリは値を使うため、渡された秘密を読めます。そのアプリや子孫のプログラムが出力・保存・外部送信すれば漏れます。起動するコマンドを信頼できることが前提です。

親から引き継ぐ環境もある。

runは、起動元の環境変数も引き継ぎます。KINKO_PASSWORDは大文字小文字を問わず除外しますが、他の既存の秘密をすべて自動で取り除くわけではありません。

金庫のうちテンプレートで参照していない値を、runがまとめて追加することはありません。一方、起動元の環境にすでにある秘密は別です。kinkoは、AIやアプリを完全に隔離する装置でも、侵害された端末を守る装置でもありません。

現在の提供状況・技術的な根拠（2026年10月12日時点）

現在はローカルCLIの候補（prerelease）です。このページは使い方の説明資料で、製品GUIではありません。GUI、クラウド同期、チーム共有、自動更新を提供済みとして描いていません。
