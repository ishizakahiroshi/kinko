実装した日常操作と保存保護

  • 排他的な directory 作成で writer lock を取り、Open 時の暗号文 SHA-256 snapshot と保存直前の現物を照合します。別 process の同時 init は1件だけ公開し、stale add/rm/save は競合として拒否します。保存対象が消えた場合や、新しく作った Vault が既存 file を指す場合も ErrConflict を返します。
  • 既存 symlink と親 directory を正規化し、同じ canonical path の lock を共有します。通常エラー時は lock と暗号化 temp を片付け、crash lock は自動で奪いません。
  • age 復号を認証された EOF まで読み切ります。複数 chunk の末尾空白、切断・改変、余分な JSON、無効 version、重複 field と不正 secret 型を拒否します。正当な空文字列と format 1、ID のない旧 format 1 は維持します。
  • 新規 vault と export は完成済み暗号文を hard link で一度だけ公開します。既存 destination を上書き・削除せず、論理 vault_id と未知の任意 metadata を保持します。既存 file の保存は同 directory 内の暗号化 temp から rename します。
  • init/list の余分な引数、空の名前、不正 option を password 入力や書込みより前に拒否します。add の複数語を space で結合する既存契約を保ち、先頭が hyphen の名前・path は -- で明示できます。
  • non-TTY input は必要な1行だけ読み、run の子 stdin を先読みしません。get は値のみ・改行なし、list は名前のみです。get の write error / short write は安全な診断で失敗し、値を error に含めません。
  • run は子 stdin/stdout/stderr と exit code を維持します。missing reference なら子を起動せず、password 環境変数は大小文字を問わず子へ引き継ぎません。
  • provider の cancel / deadline と結果が競合したときは中止を優先します。Windows verification 後の credential 読取失敗は追加 password fallback へ進めず、Linux は no-prompt と無効 object path を区別します。
  • 予約名のみの template と、値を表示せず存在だけを調べる example を追加しました。main の保存競合改善、scanner の NUL・mask・短い needle 対策と portfolio は統合後も保持しています。

互換性と保証の境界

  • 競合を自動 merge / retry しません。最新 vault を開き直して再操作します。個々の Vault 値の goroutine 同時利用は非対応で、独立した Open を使います。
  • 旧 format 1 は ID がなくても読めます。旧 source の export は先に source を保存して ID を付けます。その後 backup 作成が失敗しても source の metadata 付与は残り得ます。
  • 新規作成と export は os.Link 必須です。FAT / exFAT など hard-link 非対応 FS は非対応で、安全に失敗します。未検証 FS を対応済みとはしません。
  • 保証は協調する現行 writer と、安定した canonical path に限ります。hard-link 別名、network / sync FS、旧・非協調 writer、第三者による親 directory / symlink / lock 差替えは排他保証の外です。
  • crash lock は自動回収しません。全 writer の終了と正規化された対象を確認してから、残った空 lock のみを手動削除します。経過時間や PID だけでは安全を判定できません。
  • 暗号文 temp の file sync は行いますが、directory metadata の fsync や複数世代 backup はありません。完全な電源断耐性は主張しません。公開後の lock cleanup に失敗した場合は保存済みの可能性があり、開き直して確認します。
  • 誤 password、入力拒否、認証エラー、競合、公開前の失敗は元の暗号文を保持します。OS cleanup 自体が失敗して temp が残る場合でも、その内容は暗号文です。
  • get の出力先が途中で失敗する前に送られた bytes は取り消せません。run で渡した個別値の扱いは子 command の信頼境界です。
  • provider の path-based 登録 route は維持します。端末解除には登録時の path を使います。Windows verification 後の credential 失敗は停止し、password を明示利用する場合は別 invocation の --master-password を使います。
  • Go 1.25 は source の最低言語版です。日常利用には security patch を含む現在サポートされる安定版を推奨し、CI は Go 1.27.2 に設定しています。README/examples に同説明を追記しました。
