普段の使い方と、PC外保存が成立する条件
  1. 初回に保管先と控えを用意し、実コピーを別の場所で開いて必要項目を確認します。空の金庫を開けただけでは足りません。
  2. 以後はいつものコマンド。書き換える前後を暗号文のまま残し、接続できるときに別媒体・別PCへ追記します。通常の起動やgetは接続待ちにしません。
  3. 切断中もlocal世代が保存できれば変更できます。「PC外はどの世代までか」と未転送数を表示し、次の変更時か明示転送で再開します。常駐転送・転送時間の保証は最初の範囲に含めません。

保存先未設定でも「このPC内だけの保護」で始められます。この間は外部queueも未転送による保持固定も作らず、古いlocal世代は通常の保持規定で整理します。新しい外部accountや課金、kinko専用の接続情報保管は必須にしません。既存backupに渡す場合、実コピーを読戻せない間は「到達未確認」です。

別partitionは別媒体ではありません。同じ鞄の外付けdiskはPCと一緒に失うことがあります。普通の同期folderや削除を伝えるミラーも独立backupとは別です。独立した媒体・場所、削除非連動、保持期間を実物で確認します。

未設定と、設定後の切断は別です

  • 後で初めて設定：その時点で残る全確定世代と最新baselineを転送対象にします。既に整理した世代は戻りません。設定途中の中断や新しい変更も対象から漏らしません。
  • 設定済みで切断：未転送世代を消さず保持。容量が満杯になれば書込みを止め、読出しは続けます。
  • 意図的に解除：未転送の期間・世代数・変更件数と、最新値や変更前値のPC全損保護を失う範囲を示し、本人の明示確認後だけ転送待ちを解除します。local世代は即時削除せず、通常保持へ戻します。他の保存先の待ち状態と保護は残します。容量不足で自動解除しません。

保存先の変更は、新しい保存先を先に確認してから旧先を解除するのが既定。PC外に既にあるcopyは解除時も消しません。

転送前後に登録した媒体・接続先のidentityを照合します。媒体が外れて同じpathがPC内folderになっても、そこへ代替保存せず「PC外成功」を進めません。物理的な別置きは本人の確認も必要です。転送は新規名への追記のみ。元の削除やlocal世代整理を転送先へ伝えません。同名別内容なら止めます。network filesystemは中断・読戻しの受入が必要で、原本の排他保証をそのまま流用しません。外部の認証を失えば、コピーが残っていても取り出せない場合があります。

保存順は「前世代 → 変更後候補と台帳の耐久保存 → 原本を安全置換・耐久確認 → 確定台帳を保存 → 成功通知・PC外へ」です。fileだけでなく公開先directoryの保存完了も確認します。queue登録前に止まっても、確定世代と転送receiptから未転送分を再構成します。中断候補と確定世代を区別し、原本・世代・台帳が一度に更新されるとは主張しません。正常copyを削って空きを作り、無理に続ける動作は採りません。

誤パスワード・破損・未対応形式は正常世代として昇格させません。現行保存には自動世代やdirectoryの耐久確認がないため、この順序は新しい製品変更案です。

金庫IDだけでなく、暗号文のhash・世代・password世代の対応を照合します。台帳は標準ageで暗号化し、項目名や値、平文内容のhashを外へ出しません。日時だけで世代を判定しません。

読戻した実コピーを認証終端まで復号し、形式と必要項目を確認します。件数だけの一致では不足。同じPCのcache確認、別端末での控え入力、実項目の確認を分けます。古いIDなしformat1はbaseline hashと台帳で対応を記録し、不明なら勝手に統合しません。

暗号化台帳の詳細表示には対応する解除が必要です。未解除・読めない旧台帳を「未転送0」「保護済」と推定せず、関連世代も削りません。通常getにbackup用の追加解除は求めません。成功した段階だけ日時を進めます。失敗時も最後の成功と失敗理由を併記。過去の検査は将来の保存や媒体紛失を保証しません。

現行の復号・終端・形式検査

パスワード紛失への備え。新しい復旧鍵は必須にしない

最初は、コピーに対応する既存パスワードを紙等へ控える案を推奨します。保管先の別名、パスワードの世代記号、取得方法も一緒に記録し、データとは同時に失わない場所へ。金庫の中だけに保存するのは循環します。

  • 控えを盗まれたら：同じパスワードの現金庫も開けます。紙の再発行では古い紙・写真・暗号文を遠隔失効できません。
  • パスワードを変えたら：新copyと新控えで確認し、旧世代に必要な旧控えも残します。未接続媒体や保持lock内の古いcopyは自動では変わりません。
  • 端末解除がまだ使えたら：正常原本を開き別パスワードでexportする現行経路があります。ただし全OSの実機受入は未完了。providerは新PCへ自動移行しません。
  • 漏洩したら：金庫のパスワードを変えるだけで、既に読まれたサービスのsecretは無効化できません。発行元での失効・再発行も別に必要です。

現行の別パスワードexportは、対応パスワードでそのまま開けるformat1。自動で毎回作り直すには別パスワードを入力するか保存する必要があり、普段の負担と秘密の管理が増えます。初期案では手動の補助経路にとどめます。

別password export · 端末解除 · pathとの対応

ageの制約を確認済み

使用中のage v1.3.1では、パスワード用scrypt recipientを他のrecipientと同じfileに混ぜられません。パスワード＋復旧鍵、2つのscryptパスワードを同居させる案は採れません。

独立した公開鍵方式を後で加えるなら、解除済documentを別の標準age fileへ暗号化する案です。現在のOpenではそのまま読めず、専用の検査・復元経路が必要。暗号化済金庫をさらに包むだけでは、内側の忘れたパスワードが必要なままです。format1の内側構造と外側の暗号互換性は別。新鍵に変えても古いcopyは旧鍵のままです。

公式を2026-10-12取得：age v1仕様 · v1.3.1 API · 公式実装。独自暗号や未確認の混在方式は提案しません。

事故後：元を壊さず戻し、バックアップへ逆流させない
  1. 元の金庫とcopyを保全。保存・同期の監視対象外に、空の復元先を用意します。
  2. 正しい金庫と世代を選び、新しい名前へコピー。既存fileがあれば停止します。
  3. その世代の控えで開き、形式と必要項目を確認。「開くが必要項目なし」は成功としません。
  4. 項目だけの事故なら必要項目だけを現在金庫へ戻します。全体復元なら確認した別金庫へ明示的に切り替え、元は残します。
  5. 復元先は転送を休止した別の運用系統にします。新baselineを確認してから再有効化し、旧保管先へ古い状態や削除を自動で送らせません。新pathの端末解除も別途設定します。

この統合手順は新機能案。現行はcopyを KINKO_VAULT に指定して対応passwordで開く手動経路です。「復元先で開けた」と「普段使う金庫の切替完了」は区別します。

暫定既定案は、localで30日以内の全変更＋最新32世代。短期のミスと低頻度利用に備える設計上の仮置きで、測定値ではありません。最後の正常・復元確認済み・設定済み保存先の未転送世代と中断候補は別途保護します。未設定には外部未転送の保持固定を付けません。明示解除で外れるのはその保存先の保持固定だけです。

容量枠512 MiB、80%で警告を仮置き。金庫全体を毎回残すため、容量は「暗号文サイズ×世代数＋台帳・一時領域」が目安です。枠を超え、保護対象しか残らなければ書込みを止め、読出しは続けます。

PC外は初期提供で自動削除しません。90日ごとの容量点検は運用例で、90日で消す意味ではありません。満杯なら未転送になります。既存backupが独自期限で削除する場合はその期限を別表示します。

通常のrmで消すのは現金庫の項目。履歴には昔の秘密が残ります。秘密そのものを使えなくするには、まず発行元で失効させる必要があります。

履歴も消す場合は別の明示操作で、全世代・export・媒体・サービス履歴を棚卸しします。金庫全体の世代を消せば他の項目の復旧点も失うため、残す項目の新baselineを確認してから判断します。保持lock中は消せず、未接続媒体、所有外copy、媒体残留まで完全消去は保証しません。「確認済先から除去」「未処理」「期限待ち」を分けます。

最初の提供範囲、後段の拡張、検証の境界

最初はlocal世代・既存保管先への追記・正直なstatus・非上書き復元を一組にします。後段は必要に応じて直接サービス接続、常駐転送、独立公開鍵の復旧copyを比較します。現在のCLAUDEはcloud sync/network serviceをscope外としており、採用時には明示的なscopeとreference改訂が必要です。今回は変更しません。

後続の検証は合成データで、初回追加、全保存段階の中断、容量・権限、競合・二重実行、未設定の通常整理、初回登録の中断・同時変更、設定済切断の未転送保護、意図的解除と保存先変更、同期削除、別vault・旧IDなし、誤password・破損・新version、旧provider、非上書き復元、逆流、保持と完全消去の限界を確認します。全項目の期待値をメモリ内比較し、平文file/logを作りません。

今回実施したのは固定source・前調査・公式ageの読取りと文書検査。製品のbuild/test、実金庫、credential、account、実保存先接続、復元実験は行っていません。全OSの実機受入も今後です。

HTMLの1280/500実表示は手元検収待ち。クラウドChromiumの既知socket EPERM制約により、ここで描画成功とは記録しません。静的検査と実表示は別です。
