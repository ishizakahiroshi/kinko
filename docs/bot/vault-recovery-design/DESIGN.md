## 1. 推奨は「自動世代保存＋削除を伝えないPC外コピー＋解除控え」

普段の金庫は今のパスワード暗号化のまま維持する。追加・更新・削除の前後を暗号化したまま世代保存し、PC外へ一方向に追記する。対応するパスワードを紙などへ控え、データと同時に失わない場所へ置く。PC外のコピーを実際に別の場所で開き、必要項目が取り出せた世代を記録する。

- **便益**: 普段の `get` を妨げず、書き出し忘れを減らす。誤操作直前だけでなく、初回に登録した秘密と最新更新も守る。旧PCの端末解除や新しいサービス契約に復旧を依存させない。
- **不利益**: 世代分の容量・書込み待ち時間が増える。PC外への未転送分はPC全損で失う。紙の控えを盗まれると、同じパスワードの現金庫も開ける。消した昔の秘密は残る。保存不調時は読めても変更できない場合がある。
- **成立条件**: 動作確認したローカル保存領域、PCと故障・削除を共有しない実保存先、対応する解除控え、PC外からの読戻し確認がそろうこと。実保存先は未指定であり、「PC外保護済み」とはまだ言えない。
- **選ぶ理由**: 復旧に必要な操作を少なくし、忘れる秘密を増やさず、既存暗号文を対応CLIで扱える利点が利用者にある。実装のしやすさを選定理由にしない。

初期設定 → 保存先と解除控えを用意し、別の場所で一度開く。
普段 → いつものコマンド。変更前後を自動保存し、接続時にPC外へ追記。
事故後 → 正しい世代を選び、控えで別の場所へ復元。確認後だけ利用を切り替える。

全コピーを失えばデータを再生できず、残る全コピーの解除手段を失えば開けない。侵害済OS・悪意ある管理者・全媒体と全解除情報の同時喪失に耐える提案ではない。

## 2. 4つの仮説をそのまま採用しない

| 仮説 | 足りない点・過剰な点 | 本提案の補正 |
|---|---|---|
| 更新・削除前を保存 | 作成直後の空金庫だけでは初回secretを救えない。更新後しか存在しない値も漏れる | 前世代と変更後世代を先に確定保存。追加・初回追加も対象 |
| PC外に削除非連動コピー | 同期folder、同じ物理disk、PCと一緒に盗まれる接続媒体では条件不足 | 実媒体の故障範囲を確認。転送は追記のみ、元の削除・整理を送らない。未転送を明示 |
| 解除情報を別保管 | 金庫だけに記録すると循環する。独立passwordを毎回自動使用するには別の秘密保存が必要 | 最初は既存passwordの控え。password世代との対応を記録し、紙の漏洩・更新・旧世代残存も扱う |
| 実復元確認で準備完了 | 一度成功しても最新世代・新端末での成功を証明しない。毎回のgetを塞ぐのは過剰 | 存在・内容一致・復号・項目・別端末の確認を別々の時刻と世代で表示 |

## 3. 現実に成立する選択肢の比較

いずれも正常コピーと解除手段の両方が必要。同じ「復旧可能」の軸で比べる。下記Bのみ推奨。Cを現在のscope外という理由だけで除外しない。

| 軸 | A 手動export＋独立媒体 | B 自動世代＋既存の保管先へ追記【推奨】 | C 製品が外部サービスへ直接保管 |
|---|---|---|---|
| 誤更新・誤削除 | exportに含まれた時点まで。操作間は失う | 毎回の変更前後を保存、保持範囲内 | 同じlocal世代保存を併設すれば同等 |
| PC全損 | 最後に別置きしたexportまで | 最後にPC外で読戻し確認した世代まで | 最後に外部で読戻し確認した世代まで |
| 普段の負担 | 都度exportと媒体管理。忘れやすい | 初期設定後は自動。切断媒体は接続が必要 | 初期接続後は自動。認証・回線障害の対処 |
| password紛失 | 控えまたは別password exportが必要 | 対応世代の控え、または残存端末解除 | クラウドaccountへの復帰だけでは暗号文を開けない |
| 削除の隔離 | exportを独立に保管した場合だけ | 追記先へのdelete伝播なし。保存先の独立性は要確認 | versioning・保持lock等の具体設定が必要。単純syncでは不足 |
| 利点 | 現行機能で備えを始められる | 取り忘れを減らし、保存先の選択と持出しを保てる | 対応先を絞れば一元的な状態確認ができる可能性 |
| 不利益 | 最新値と前後世代の取り漏れ | 実媒体・既存backupの性質が異なる。容量・切断が利用者に残る | account喪失、継続費用、サービス停止、永続権限を新たに持つ |
| 判断時点 | いまでも手順として選べる | 実装着手前に方式を採否、実利用前に保存先受入 | 既存保存先で目的を満たせないと分かった後 |
| 改修・検証の概算 | 手順整備2–5人日＋個別環境確認 | ローカル＋追記＋復元・状態表示で4–8人週、複数OS受入2–4人週追加 | Bに加え対応サービス1つにつき3–6人週以上の幅を仮置き |

工数は比較用の未測定の概算で、1名経験者・仕様確定・既存CLI活用を仮定。期限、費用、完成約束ではない。媒体保証やOS固有障害で増える。作る手間は上記欄に閉じ込め、推奨の根拠には使わない。Aは現行からの暫定対策、B/Cは新機能案である。

## 4. 最小の実用範囲とPC外の保存契約

### 最初に提供する範囲（全て未実装）

CLIは維持。ローカル世代保持、状態確認、手動または保存後の一方向転送、非上書き復元を一組にする。外部サービスのaccount・tokenをkinkoに持たせない。利用者が用意した独立媒体／別PC上の領域を、書込み可能な保存先として指定する。local世代は原本金庫directoryの外に、OSの利用者データ領域内の専用collectionとして自動で用意する。同じdisk上なのでPC全損保護とは数えない。通常の起動・getに毎回設定や媒体接続を要求しない。

別PC領域をOS経由で使う場合はnetwork filesystemでの公開・読戻し・中断復帰を個別検証する。ローカル原本は対応するローカルfilesystemに置く。未受入のnetwork/sync filesystemへ原本を置いてwriter安全性を保証しない。

既存backup製品にlocal世代を拾わせる経路も使える。ただしkinkoがPC外から実データを読戻せなければ「外部サービスに任せた・到達未確認」と表示する。ジョブ成功通知だけを復元確認に代えない。

### PC外として数えてよい条件

1. 原本・local世代と別の物理的故障範囲。別partitionは数えない。同じ机の外付けdiskは内蔵disk故障には備えられるが、PCと一緒の盗難・火災には未対応。別置き／別拠点の実態を利用者が確認する。ソフトだけで証明できない。
2. 登録時と毎回の転送前後に、OSが示すvolume identity／別PCの接続先・share identityと、保存先に置く不透明なcollection markerを照合する。path文字列やmarkerだけで別媒体と判定しない。unmount・切断後に同じpathがlocal directoryへ落ちても、そこを自動作成・代替使用しない。identityが不明・変更・同一diskなら外部成功を進めず再確認する。OS情報も物理的別置きの証明ではなく、その範囲は本人確認として別記録する。
3. 世代ごとの新規名で追記し、既存名の内容が異なれば停止。転送先へ元のrm、source消失、local保持整理を伝えない。
4. 普通の双方向sync、ミラー削除、trash期限が不明な共有folderは独立backupの条件を満たしたと扱わない。保持設定・権限・元を消した合成データの読戻しを確認する。
5. 転送は暗号文と暗号化した台帳だけ。認証情報は既存OSの接続管理に委ねる。新account、接続設定、課金、実データ転送は今回行わない。
6. 設定済みの保存先が切断中なら暗号化queueを保持。書込みのたび一度だけ短い時間上限で転送を試す。getでは待たない。次の書込み、明示的な転送、または既存backupのスケジュールが再試行機会。常駐daemonや時間保証は初期範囲に入れない。
7. 容量不足・権限不良・認証紛失・応答不明なら最後の外部成功時刻を進めない。指数backoff等の自動常駐再試行は後段案。拒否・取消・不明な書込み結果は内容と世代を照合してから人が再開し、同じ操作を盲目的に繰り返さない。

### 未設定・切断・解除を分ける（保存先単位の状態）

| 状態 | queueと保持 | 次の操作／利用者への表示 |
|---|---|---|
| 外部保存先を一度も設定していない | 外部転送queueを作らず、未転送pinも付けない。通常のlocal保持規定は適用 | 「PC内のみ。古いlocal世代は保持規定で整理される」。未転送0ではなく「外部保護は未設定」 |
| 初めて保存先を設定する | 登録時のsnapshotで現存する全確定世代をその保存先の対象へ登録し、未確認分をpin。登録中の新しい確定世代も漏れなく追加 | 「現存N世代を転送待ち。過去に整理済みの世代は対象にできない」。原本の最新正常baselineを必須にし、登録完了前は外部準備中 |
| 設定済みだが切断・故障・未転送 | 保存先ごとに、対象登録した確定世代と確認receiptの差分をqueue/pinとして維持 | 接続後に同じ世代を照合して再開。local容量が保護世代で満杯ならwriteを止め、readは継続 |
| 意図的に保存先を解除・変更する | 単なる切断を解除と解釈しない。専用の明示操作でのみ対象のqueue/pinを解除する。別保存先のpinとlocalの正常/検証済み保護は残す | 未転送の世代数・期間・追加/更新/削除の件数と「この期間の最新値や変更前値はPC全損で失い得る」を表示し、本人が保護放棄を確認してから解除 |

初回登録では最初に登録対象の暗号化台帳を耐久保存してから転送を始める。登録中断は元の未設定へ黙って戻さず「設定途中」とし、登録snapshotとそれ以降の確定世代から対象を再構成する。原本の新しい書込みと登録を同じcollectionの協調lockで調停する。旧password世代の暗号文をcopyできても、復号確認は未確認のまま残す。

意図的解除は暗号化台帳へ記録し、失う保護範囲を本人が確認した事実を残す。値や項目名を通常の診断logへ出さない。解除してもlocal世代を即時削除せず、以後の通常保持規定で整理され得ることを示す。PC外に既にあるcopyは削除しない。保存先変更は新保存先を先に登録・確認してから旧保存先を解除する手順を既定とし、新先未確認でも旧先の未転送保護を放棄する場合は同じ明示確認を必要とする。容量不足を理由に自動解除・黙ったqueue破棄はしない。

保存先未設定でもlocal保護で使い始められる。初回のinitで「PC全損・解除情報喪失は未対策」と一度説明し、statusと変更時の短いstderrで不足を示す。毎回getのstdoutへ警告を混ぜない。全ての備えを済ませるまで利用不能にする案は採らない。

## 5. 世代の内容と保存順序

### 何を残すか

| 操作 | 原本公開前に必要な世代 | 意味 |
|---|---|---|
| 新規作成 | 空金庫G0（確定済と未公開を区別） | 識別子・形式・保存経路の基準。secret保護完了とはしない |
| 初回secret追加 | G0＋追加後G1 | G0だけを保存しても初回secretは救えない |
| 追加・更新 | 現在のG(n)＋変更後G(n+1) | 更新前の値と最新の値の両方 |
| 項目削除 | 削除前G(n)＋削除後G(n+1) | 復旧する旧値と現在の意図を区別。通常rmは履歴消去でない |
| 書込みなしのget/list | 新世代なし | 読むだけで世代容量を使わない |
| 既存金庫への機能導入 | 読める原本の暗号文をbaseline保存 | 設定だけでsourceを書換えない。読めない原本を正常世代にしない |

世代は金庫全体の暗号文。名前も値も平文fileやlogへ出さない。新しい世代は単一scryptのformat1を維持。現passwordを使うSaveの範囲で生成し、backupのために平文passwordの永続configは追加しない。

### 書込みtransaction（提案仕様）

1. 正規化pathのwriter lock、読み込んだ暗号文snapshot、金庫identityを照合する。lockを時間/PIDだけで奪わない。競合なら再openして意図を再確認し、古い内容で再保存しない。
2. 復号・構造検査に通った現在暗号文を、世代領域へ別fileとして新規・非上書きで保存する。tempへのfile Sync/close、非上書き公開、その世代directoryのSync、読戻しhashを完了させる。hard linkによる内容共有はしない。正常な既存同一hashがあれば再利用する。
3. 変更後の暗号文をメモリからtempへ書き、暗号化終端Close、file Sync/close、読戻しhash、復号終端、形式・全項目の意図した内容一致を検査する。新規の変更後世代を非上書き公開し、そのdirectoryのSyncを完了する。次に暗号化台帳へ「未公開候補」のイベントを追記し、そのfileと台帳directoryのSyncまで完了する。ここまでの耐久確定が原本置換の必須条件。値・項目名・値のhashを平文台帳へ出さない。
4. 原本用tempも同filesystemでfile Sync/closeしてから安全置換し、原本directoryのSync、原本読戻しhashの一致まで確認する。原本を先に消さない。その後に台帳の「変更確定」イベントを追記し、fileと台帳directoryのSyncを完了する。この境界まで通過して初めて変更確定の通知・exit 0を許す。
5. 転送queueは唯一の保存記録にしない。有効な保存先の登録対象世代・耐久確定した新世代・台帳の確定イベントから、転送先ごとの確認receiptを差し引いて未転送集合を再構成できるようにする。保存先未設定ならqueueも外部未転送pinも作らない。queue登録前で中断しても取りこぼさない。変更確定後にのみPC外へ送り、転送先の読戻しとidentity確認を経てreceiptを記録する。
6. いずれかの耐久操作、原本読戻し、確定台帳更新、lock解除に失敗して原本置換後か判然としない場合は「未確定／変更済の可能性」。失敗を未変更と断定せず、次回原本hashと前世代・未公開候補を照合してG(n)/G(n+1)/第三の内容を判定する。G(n+1)なら原本と世代の耐久確認・台帳の確定追記を完了し、未転送集合を再構成する。操作そのものを自動再実行しない。第三の内容は競合隔離する。

原本・世代・台帳を一度にatomic更新できるとは主張しない。電源断時は先に残った候補があり得る。復旧画面は「最後に公開確認した世代」と「中断候補」を分ける。候補の復号成功だけで利用者が確定した変更としない。

現行Saveは同directory tempのSync/closeとrenameを行うが、directory Sync・自動世代保持はない。この順序は製品変更案であり既存保証ではない。対応OS/filesystemで耐久保証できない場合はその構成を受入対象から外すか、弱い保証を明示する。非協調writer、hard-link別名、network/sync FSの排他保証は現行同様に無条件ではない。[S1][S2][S5]

### Readとwriteの失敗方針

| 状態 | 既存secretを読む | 変更する | 表示・保全 |
|---|---|---|---|
| PC外未設定 | 原本が正常なら可 | local前後世代が保存できれば可 | 「localのみ／PC外未設定」。queue/pinなし。通常local保持 |
| 設定済みPC外が切断・未転送 | 原本が正常なら可 | local前後世代が保存できれば可 | 「PC外は世代Xまで」。未転送pinと件数を保持。満杯ならwrite停止 |
| local世代の容量・権限不足 | 可 | 原本公開前に停止 | 元の原本と最後の正常世代を残す。勝手に古い保護世代を削って続行しない |
| 原本破損・誤password・未対応version | 不可（別世代の復元へ） | 停止 | 誤passwordか破損か断定しない。既知正常世代を上書きしない |
| writer競合・二重実行・残lock | 読める正常snapshotなら可 | 停止 | 別writerを奪わない。新たに開いて再確認 |
| 原本確定後にPC外転送失敗 | 可 | local保存済の結果は維持 | 「変更は保存済、PC外保護未更新」。変更失敗として二重実行させない |
| 原本置換結果が不明 | 正常な確定snapshotを明示的に確認後 | 照合完了まで停止 | 「保存結果未確定」。成功時刻を進めない |

変更が確定した場合はexit 0＋短いstderrでPC外遅延を示す。変更未確定/停止は非0。backup不足の機械判定は別のstatus出力で行い、非0を受けたscriptがset/rmを盲目的に再実行する契約にしない。これは新CLI契約の案。[S5]

## 6. 金庫・世代・中身の確認

- **金庫identity**: 復号した `vault_id` を内部で比較する。同じvault_idでもexport passwordと内容は異なり得るため、IDだけでは同じ世代としない。
- **世代identity**: ciphertext SHA-256＋ランダム世代識別子＋親世代hash＋操作transactionの関連を暗号化台帳に保存する。日時は補助で、時計巻戻りを識別方法に使わない。新規名は排他作成。既存名でhashが違えば競合停止。
- **台帳**: 世代hash・金庫ID・親・形式・password世代記号・作成/公開/転送/検査状態を含め、同時点passwordの標準ageで暗号化。外の列挙情報は不透明ID、暗号文hash、サイズ等必要最小限。名前・値・password・平文内容hashは出さない。台帳喪失時は暗号文を個別に検査し、「系譜不明」として手動選択へ落とす。暗号化は出所の独立証明ではなく、悪意あるpassword保有者やOSは対象外。
- **旧format1（IDなし）**: 読むだけでIDを追加しない。初回baselineは原暗号文hashと内部collection IDを暗号化台帳で紐付ける。次の正常な書込みで付与するvault_idとの橋渡しを台帳へ記録。橋渡し不明なら自動統合せず、利用者が内容確認する。現行exportはIDなしsourceを先にSaveする点に注意し、この新設計の「source非変更」と混同しない。[S1][S2][S3]
- **復号**: ageの認証終端まで全体を読む。JSON1回Decodeだけで終わらず、形式・重複key・値型・終端・versionを検査。古いCLIで新versionを勝手に読み替えない。[S1][S2]
- **必要項目**: 作成時はその操作の期待する全項目と値をメモリ内で比較。初回設定と復元練習では、選んだ必要項目の存在と期待した内容を本人が確認する。件数一致だけを全項目一致としない。結果だけ記録し実値をlogに残さない。
- **PC外の確認**: 成功したput/コピー終了だけでは不足。PC外の確定fileを新たに開きhashを照合し、可能なら独立経路で別端末へ取り出して控えで復号する。OS cacheや同一sourceを読んだだけの検査を別端末受入と呼ばない。

## 7. 解除を忘れたとき・互換性

### 推奨する控え

新しい復旧鍵を初期案の必須条件にしない。対象collectionの短い別名、password世代記号、その世代に対応する既存master password、コピーの保管先と取得方法、必要なCLI形式を紙等へ控える。実秘密を本資料やリポジトリ、screen logへ書かない。控えはPC・backup媒体と同時に失わない施錠場所等へ置く。単なる「金庫内に保存」は不可。

初期設定は控えから入力してPC外コピーを復号できるところまで確認する。毎回のgetに控えの入力や追加passwordを求めない。控えを忘れただけなら記憶password・正常provider・既存の別password exportを探す。

- 元passwordを忘れても使用可能な登録済OS providerと原本が残れば、現行の明示exportで別passwordのcopyを作る経路がある。OS実機受入は未完了であり救済確約ではない。[S3][S4]
- PC全損・OS user削除・provider失効時はそのproviderを当てにしない。providerはpath由来、暗号文にcredentialは入らず、新PCへ移らない。同じvault_idの別password exportへ旧providerを流用しない。[S4]
- 現行の別password exportは独立した単一scryptのformat1。新passwordでそのfileを開ける。元passwordを変えても過去のexportは変わらない。[S1][S2][S3]

### 控えの更新・喪失・漏洩

passwordの変更／別passwordのexportで世代記号を分ける。新copy＋新控えで復元確認してから通常利用を切り替える。古い暗号文を残す間は対応する古い控えも必要。全部を新passwordへ再暗号化したつもりでも、未接続媒体やimmutable履歴に残る旧copyは旧passwordで開く。

控えを紛失し残存経路があれば新しい控えを作り、必要なら新passwordの独立copyへ移す。紛失を漏洩疑いとして扱う場合は、保存している各サービスのsecretをそのサービスで失効・再発行する対応も必要。金庫password変更だけでは既に漏れたsecretを無効化できない。

紙を再発行しても、昔の紙・写真・既存暗号文を遠隔無効化する仕組みはない。控えは現金庫にも通じるという不利益がある。全copyと解除経路を棚卸ししても所有外copyの消滅は保証できない。

### ageの確認結果と代替案

kinkoはage v1.3.1を使用。公式v1仕様ではscrypt stanzaがあるfileに他のstanzaを混在させてはならず、Go `ScryptRecipient` も唯一recipientを要求する。master password＋X25519復旧鍵を同じage fileへ足す案、2つのscrypt passwordを同居させる案は不可。[A1][A2][A3]

自動更新と「日常passwordを開けない独立の復旧秘密」を両立する後段案は、解除済documentを**別の標準age公開鍵暗号文**へ暗号化する方式。オンラインに置くのは公開recipientだけ、秘密identityは別保管。既存password暗号文をさらに包むだけでは、復旧鍵で外側を開けても忘れた内側passwordが必要なまま。独自の鍵ラップは設計しない。

この別fileは現行kinko OpenのScryptIdentityだけでは直接読めない。ageでの復号とformat1検査、新しいpasswordでの別金庫作成という明示restore経路が必要。内側JSONがversion1でも外側recipientの互換性は別である。新しい復旧鍵を入れても古いfileは旧鍵のまま、漏洩後の既存copyを無効化できない。公開鍵は誰でも暗号化できるので出所の証明にもならない。現行age APIの新システム向け推奨はHybridRecipientを含むため、将来選定では公式の当時の推奨と脅威モデルを再確認する。今回X25519方式の採用・実装はしない。[A1][A2]

別passwordの自動exportでは、そのpasswordを毎回入力するか、利用時に取り出せる秘密保存を増やす。今回の「普段を増やさない・解除秘密は別置き」に不利益があるため、手動の補助経路にとどめる。

## 8. 復元は原本を上書きせず、保存先へ逆流させない

1. 壊れた原本と世代領域を保全。復元元をread-onlyで扱い、backup監視・自動転送・保持整理の対象外に隔離した空の復元先を選ぶ。
2. 別名・別namespaceへ暗号文を排他作成。既存fileがあれば停止し、上書きも先行削除もしない。
3. 狙った金庫・世代・password世代を照合し、控えで認証終端まで復号、形式、必要項目を検査する。初期練習では空G0だけを見て成功としない。
4. 項目だけ誤削除した場合は全金庫を巻き戻さず、隔離copyから必要項目をメモリ経由で現在金庫へ明示的に取り戻す。その変更にも通常の前後世代保存を適用。現行には統合restoreはない。
5. 金庫全体を戻す場合は確認済復元先を利用対象として明示的に切り替え、旧原本を保持。新しいpathのproviderは別途設定し、旧providerを自動移植しない。
6. 復元直後は転送を休止した別の運用系統として扱う。同じvault_idを保持するcopyでも新しいstream/namespaceを割り当て、旧backup collectionへ自動で同期・削除・整理を送らない。必要な項目の採否と新baselineを確認してから明示的に再有効化する。

「復元完了」はその復元先・その世代・確認した項目の成功であり、現金庫の切替完了や全外部保管先の準備完了とは別。必要項目が欠けた正常な古い世代は「開けるが不足」と表示する。

## 9. 正直な状態表示

単一の緑チェックで全部を表さない。statusには、現在の変更確定世代、local最終正常世代、外部到達確認世代、未転送数、控えで開けた世代・日時、別端末の最終確認、保存先の独立性の確認範囲を示す。秘密とvault_idを通常画面へ出さない。[S5]

例（全て架空・表示設計）:

- 「このPC内のみ：変更は保存済。PC外の保存先は未設定」
- 「PC外は1世代前まで：直近1件は未転送。媒体を接続して転送してください」
- 「PC外コピーは確認済：控えでの復元練習は未確認」
- 「世代G12は別端末で必要項目まで確認済。現在はG14：2世代分は別端末未確認」
- 「保存結果が未確定：原本を照合するまで変更を停止」

詳細statusと台帳の追記・編集には、該当password世代を開ける解除sessionが必要。未解除・誤password・読めない旧台帳は「未確認／詳細には解除が必要」と表示し、未転送0・保護済・最新と推定しない。通常getにbackup用の追加解除を求めない。読めないepochの世代は保持整理の対象にせず保全する。既知の暗号文と台帳のcopyを転送できたとしても、そのepochの復号確認は進めない。

成功した段階だけ時刻を進める。失敗や未接続で古い成功を消さず、失敗日時・理由と併記。到達確認は後日の保持・可用性を永久保証しない。媒体紛失、password変更、保管先変更、復元後は関連する確認を古い条件での実績へ降格させる。

## 10. 保持と「本当に消したい」の両立

暫定既定案はlocalで「30日以内の全変更」と「最新32確定世代」の和集合。短期の操作ミスと低頻度利用の両方に備えるためで、公式保証・測定値ではない。加えて最後の正常世代、最後の復元確認世代、有効な外部保存先の登録対象で未転送の世代、中断候補は保護する。外部未設定の世代に未転送pinは付けない。意図的解除後はその保存先のpinだけを外し、通常保持と他の保護条件は継続する。候補の整理は確定状態の照合後のみ。

初期容量枠の仮置きは512 MiB、80%で警告。1世代は全金庫なので、おおむね暗号文サイズ×保持世代数＋台帳・一時領域が必要。更新頻度・容量は未測定。前後世代が既に同じhashなら重複保存しない。枠を超えそうなら安全な旧世代の整理を先に計画し、上の保護条件に抵触するならwriteを止める。readは続ける。最後の正常copyを自動削除して書込みを通さない。

PC外は初期提供で自動deleteを送らない。保持期間は無限保証でなく、外部媒体が満杯になれば未転送になる。90日を目安に容量と残す期間を点検する運用例を示すが、勝手に90日で消さない。既存backupサービスが独自期限で消す場合はその実期限を表示し、local規定と混同しない。

通常の項目削除は現金庫からだけ除き、旧秘密・失効済秘密は世代内に残る。確実に使えなくしたいtoken等は発行元で失効させることが先。保存領域の削除だけでは盗まれた値を無効化できない。

履歴も消したい場合は、対象項目を含む世代・export・別媒体・サービス履歴・ゴミ箱を列挙し、明示的な別操作で扱う。全金庫世代は他項目も含むため、丸ごと消せば他の復旧点も失う。必要に応じて残す項目の新しいclean baselineを作って確認するが、古いcopyはその場では消えない。immutable保持期間中は消去できない。未接続媒体・第三者copy・snapshot・SSD残留まで完全消去を保証しない。「確認済保管先から除去」「未接続先未処理」「保持期限待ち」を区別する。暗号鍵破棄も全対応鍵とcopyの管理を証明できなければ全消去の証明にならない。

## 11. 事故別の復旧範囲

| 事故 | 必要なもの・経路 | 戻らない場合 |
|---|---|---|
| 項目誤削除／誤更新 | 操作前世代＋対応解除手段、項目選択復元 | 保持外、全旧世代削除、当初から未登録 |
| 金庫file全削除／破損 | 別directoryの正常世代＋解除手段、別場所へ復元 | 同directoryだけ一括削除、正常世代なし |
| 内蔵disk全損 | 別の正常媒体・別PCに確認済copy | 別partitionだけ、未転送の最新値 |
| PC紛失／火災 | PCと同時に失わないcopyと控え | PCと同じ鞄の外付け・同じ場所の紙も喪失 |
| master passwordだけ失念 | 紙控え、または残存providerから別password export | 全解除経路喪失 |
| provider消失・新OS user | 世代に対応するpassword、別pathで明示解除 | 古いprovider登録しかなくpassword不明 |
| 保管先account認証紛失 | 別の手元copy、保存先の正規復旧経路 | 外部copyが存在しても取り出せない、他copyなし |
| 同期削除 | 削除非連動の独立保持世代 | mirrorのみ、retention期限切れ |
| 全copy喪失／全解除喪失 | いずれもkinko単独の救済なし | データ再生成・本人確認で暗号解除するserviceはない |

| 復元先既存／復元中断／再試行／転送監視 | 非上書き、旧backupへの逆流なし。再利用開始は別streamの明示操作 |
| 外部未設定で30日/32世代超の継続利用 | queue/未転送pinなし。正常/検証済み保護を守り通常local整理できる。外部保護済や未転送0と表示しない |
| 初回登録途中停止／登録と同時書込み | 現存確定世代snapshotと以後の新世代を漏れなく対象化。既に整理済みは復活しない。設定途中を黙って解除しない |
| 設定済切断で容量枠到達／意図的解除／保存先変更 | 未転送pinでwrite停止。明示確認なしにqueue/pinを破棄しない。解除後も他destとlocal保護を維持。PC外copyを削除しない |
